## v78 retro findings (the gap analysis this snapshot records)

**DEFECT-OAG-040 (fix 800efca, MTTR ~1024s) — the biggest gap.**
- Who SHOULD have caught it: the **engineer** (fold test design) and the
  **tester** (derived-state validation).
- Latent root cause (not the code fix): the fold derived status from a
  `lastStatusEvent` marker seeded only from events within a BOUNDED backward-scan
  window. The fold's correctness depended on **scan-window completeness** — an
  UNSTATED INVARIANT. Every fixture was real-SHAPE but LOW-VOLUME / single-page,
  so on the real feed (a page of 66 EstimatedArrivalChanged events) the target
  OnBlock/OffBlock/TakenOff event aged OUT of the window → the marker was never
  set → fallback "Scheduled" for every flight; Baggage tab empty for the same
  reason. The correct `actual.inGate/onGround/outGate` fields were in the
  aggregate all along (Gate/Arrival columns worked because they read fields, not
  the window-seeded marker). No test used real-VOLUME/aging fixtures, so the
  bounded-window assumption was never falsified. Recurrence of the DEFECT-OAG-018
  stuck-"Scheduled" class, escaped because validation ran on a low-volume surface.
- Owner routing: engineer.md (real-VOLUME/aging fixtures for windowed-scan folds +
  state the scan-window bound as an explicit route invariant) + tester.md
  (validate derived state on a real-volume window, not a hand-sized one). New
  experiment **EXP-092** targets CFR (windowed-scan folds that silently drop state).

**DEFECT-OAG-039 (fix e68a673, MTTR ~1023s).**
- Who SHOULD have caught it: the **engineer** (local-tooling test design).
- Latent root cause: the local FIDS signing proxy (dev tooling) captured AWS
  creds ONCE at startup and never refreshed → 403 after ~1h. No test exercised the
  credential LIFECYCLE; local support tooling was treated as fire-and-forget, so a
  time-dependent failure only surfaced when the human hit it live in the demo.
- Owner routing: engineer.md — local dev tooling gets lifecycle tests too (a
  resource with a lifetime: assert it refreshes before expiry + a call after the
  original lifetime still succeeds). Narrow single-agent behaviour, no new EXP
