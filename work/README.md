# /work — Project artifacts (RESETTABLE)

Everything an actual project produces lives here. This directory can be wiped or
restarted without touching the agents' learned process in `/process`.

Projects coexist; `ACTIVE` (a one-line file in this directory) names the one
commands default to. Manage it with `/project-switch` and `/project-list` —
never by hand-editing mid-session. Each project is self-contained: its decision
log, gate state and DORA rows are project-tagged, so switching loses nothing.

One subdirectory per project, created by `/project-new`:

```
work/<project>/
  project.md            # status (active|stopped), JTBD vision, owner, dates
  decision-log.md       # append-only log of every gate decision / why (auditable)
  architecture/
    current.md          # C4 solution architecture as it stands now
    deltas/             # one file per slice: the architecture change it made
    security/           # per-infrastructure security notes → later become policy test cases
  chunks.md             # high-level sequence of value slices ("Chunks")
  capabilities.md       # environments, test approach, CD needs for the next iteration
  items/                # THE SOURCE OF TRUTH — one self-contained file per work item
    active/<ID>.md      #   definition + dependency edges + append-only event log
    done/<ID>.md        #   completed items, moved verbatim (whole truth archived)
  views/                # DERIVED — regenerated by `make wi-project`; NEVER hand-edit:
                        #   queues (ready/rework/intake/waiting + WIP), the folded per-item
                        #   state, the dependency tree, and DORA+flow stats (.md/.json)
```

An item's state is **not stored** — it is `fold(events)` through the item's type
state graph (`process/machinery/state-graphs.json`). The **only** way to change
state is `make wi-append` (edge-checked, sole writer); everything under `views/`
is recomputed on read by `make wi-project`, and `make wi-validate` is the drift
gate. See `process/machinery/CONTRACT.md` and the `work-items` skill.

**Metrics are derived into `views/stats.*` by `make wi-project`** — the four DORA
metrics plus gross-lead-time contribution by owner, quality by stage, and
recovery/MTTR by class. Nothing is recorded by hand and nothing is stored twice.
When a change harmed a metric, the reflection lives in `decision-log.md` and
graduates to `/process/principle-failures/` when it reveals a reusable lesson.
(The retired per-project DORA CSV shards are a frozen QueueApproach archive.)

A project template lives in `_TEMPLATE/`.
